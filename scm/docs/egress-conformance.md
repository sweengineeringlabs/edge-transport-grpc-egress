# Egress conformance assessment (issue #62)

**Status:** Initial source audit; not complete. This records confirmed findings before API changes are selected.
**Source revision:** `f318b44` (`dev`, 2026-10-22).
**Governing reference:** [Agent Deployment Architecture](https://github.com/sweengineeringlabs/llm-agent-deployment-spec/blob/6a71e2ddac31579ca314919e3e54ca5c45d054cf/docs/3-design/architecture.md), especially **Two Phases**, **Direct identity accessors**, **Value Objects**, **VO constructor visibility**, **Responses Own Their VOs**, **Response Field Privacy**, **Request Construction**, and **SAF Encapsulation**. Local implementation boundaries are additionally governed by [ADR-006](adr/ADR-006-domain-first.md) and [ADR-010](adr/ADR-010-programming-over-the-interface.md).

This is deliberately a source-evidence document, not a compliance claim. Issue #62 requires a complete inventory across transport, retry, breaker, resilient composition and bearer authentication before implementation changes. The rows below capture the first confirmed construction and encapsulation gaps; other public types and method families remain to be inventoried.

## Phase and ownership distinctions applied

| Architecture rule | Egress interpretation | Evidence / enforcement to add |
|---|---|---|
| Configuration phase uses `with_<Trait>(value)` and caller-owned capabilities cross directly; it does not use request/response wrappers. | Builder/factory configuration values remain direct inputs. Do not wrap those capabilities in exposure DTOs. | Review each builder trait and factory signature; external-consumer compile tests. |
| Exposure operations use `get_*`/`list_*` with operation-specific requests and owned responses. | An operation returning policy or status must have its classified request/response pair. Direct identity/property accessors stay parameterless and use Rust accessor names. | Inventory every trait method and correlate each exposure operation with its DTO files. |
| User-provided VOs have private state, public validated construction, value semantics and no mutation API. | Retry, breaker, resilience, channel and bearer configuration are caller-supplied inputs; callers need supported constructors/builders, while struct literals and unchecked deserialization must not create invalid completed values. | Compile-fail field/constructor tests; positive constructor tests; deserialization tests that assert invalid values fail. |
| Response-owned configuration VOs are created internally by their response constructor. | Do not apply this visibility rule to caller-supplied configuration inputs. Preserve the distinction between a caller's policy value and a configuration value created only as response data. | Classify each VO by ownership before setting constructor visibility. |
| Requests use `new()` for zero or fewer than three parameters and a builder for three or more. Build requests are construction-phase parameter bundles and are explicitly exempt. | Do not blanket-wrap identity accessors or rename build requests as exposure requests. | Request/response scanner and compile-fail constructor/field tests. |
| SAF modules are private; public factory types are canonically re-exported; implementation types stay opaque. | Consumers import root-level SAF factory exports and domain-owned traits/types. Contract types remain owned by `proto-pattern`; implementations do not duplicate them. | Compile-fail hidden-module tests and canonical-export scanner. |

## Confirmed VO construction gaps

| Affected public value | Source evidence at `f318b44` | Current bypass | Required disposition | Owner / dependency | Enforcement |
|---|---|---|---|---|---|
| `GrpcRetryConfig` | [`retry/src/api/vo/grpc_retry_config.rs`](../main/retry/src/api/vo/grpc_retry_config.rs): public fields and derived `Deserialize`; `retry-std/src/saf/std_grpc_retry_factory.rs` accepts it directly and does not validate it. | A caller can construct `max_attempts = 0` with a struct literal; derived deserialization also creates the value without provider validation. | Make state private and immutable; provide the prescribed validated caller construction path; ensure deserialization validates. Keep the valid baseline `Default`. | Egress-owned; no upstream API required. | External compile-fail for field literals; invalid `Deserialize` and factory-path tests; scanner for public VO fields. |
| `GrpcBreakerConfig` | [`breaker/src/api/vo/grpc_breaker_config.rs`](../main/breaker/src/api/vo/grpc_breaker_config.rs): public fields and derived `Deserialize`; `breaker-std/src/saf/std_grpc_breaker_factory.rs` validates at `build`, but direct construction/deserialization still creates an invalid value. | Invalid values exist as completed public VOs and can cross into factory construction before its fallible build. | Make state private and immutable; provide validated public construction; make deserialization reject `failure_threshold = 0` and `half_open_probe_count = 0`. | Egress-owned; no upstream API required. | Compile-fail field literals; invalid deserialization; existing factory validation tests retained. |
| `ResilienceConfig` | [`resilient/src/api/vo/resilience_config.rs`](../main/resilient/src/api/vo/resilience_config.rs): public fields and derived `Deserialize`; validation currently occurs in `resilient-std` provider/factory. | Struct literals and direct deserialization bypass provider validation until composition. | Make state private and immutable; expose a validated construction path and validate deserialized input before it becomes a completed VO. | Egress-owned; coordinate with the retry/breaker policy construction APIs. | Compile-fail field literals; invalid deserialization; invalid factory input tests. |
| `BearerEgressConfig` | [`auth-bearer/src/api/vo/bearer_egress_config.rs`](../main/auth-bearer/src/api/vo/bearer_egress_config.rs): public fields and derived `Deserialize`; `Validator` checks only nonempty issuer/audience/subject and does not check token lifetime. | Struct literals and direct deserialization bypass even the partial validation; `lifetime_seconds = 0` is not rejected by `Validator`. | Make state private and immutable; define validated construction/deserialization for all required constraints, including lifetime. | Egress-owned; security primitive implementation remains in `edge-security`. | Compile-fail field literals; invalid deserialization and lifetime tests; builder/factory validation tests. |
| `GrpcChannelConfig` | [`transport/src/api/channel/vo/grpc_channel_config.rs`](../main/transport/src/api/channel/vo/grpc_channel_config.rs): public fields and derived `Deserialize`; defaults include an empty endpoint and zero values are accepted by deserialization. | Callers can complete invalid configs with literals or TOML, before the egress builder checks options. | Keep it as caller/file input, make the VO immutable, and validate every deserialization and builder completion path; distinguish defaults from a usable endpoint configuration. | Egress-owned; the contract/engine continues to own call TLS and compression types. | Compile-fail field literal; invalid TOML; public builder construction tests; public-VO scanner. |
| `BackendTarget`, `LoadbalancerSettings` | [`transport/src/api/loadbalancer/vo/backend_target.rs`](../main/transport/src/api/loadbalancer/vo/backend_target.rs) and [`loadbalancer_settings.rs`](../main/transport/src/api/loadbalancer/vo/loadbalancer_settings.rs): public fields and derived `Deserialize`; no validating constructors. | Invalid URL or an empty backend list can be represented directly; the builder catches these later. The valid weight range still needs an explicit ruling from the balancing policy. | Classify each as caller-provided capability input; encapsulate fields and validate construction/deserialization according to the balancing policy. | Egress-owned. | Compile-fail field literals; invalid deserialization; per-condition constructor tests; public-VO scanner. |

These findings identify real construction bypasses; they do not prescribe request wrappers or redesign exposure APIs. Existing per-factory validation remains useful defense in depth, but it does not make an invalid public VO impossible to construct.

## Inventory still required before implementation selection

- Enumerate every public trait method, DTO, VO, error, factory and canonical root export in each domain/implementation pair, including interceptor, cancellation, caller identity, TLS, load balancing, bearer auth and health types.
- Classify methods as configuration, exposure operation or direct identity accessor; map each exposure operation to request/response files and each constructor to its ownership rule.
- Recheck source paths and line-level evidence at the implementation commit, and record the required scanner or test for every row.
- Separate egress-local changes from changes that need released `proto-pattern`/`proto-svc` APIs. Keep #61's unaccepted cross-cutting migration outside this issue.
