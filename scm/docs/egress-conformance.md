# Egress conformance assessment (issue #62)

**Status:** Initial source audit; not complete. This records confirmed findings before API changes are selected.
**Source revision:** `f318b44` (`dev`, 2026-10-22).
**Governing reference:** [Agent Deployment Architecture](https://github.com/sweengineeringlabs/llm-agent-deployment-spec/blob/6a71e2ddac31579ca314919e3e54ca5c45d054cf/docs/3-design/architecture.md), especially **Two Phases**, **Direct identity accessors**, **Value Objects**, **VO constructor visibility**, **Responses Own Their VOs**, **Response Field Privacy**, **Request Construction**, and **SAF Encapsulation**. Local implementation boundaries are additionally governed by [ADR-006](adr/ADR-006-domain-first.md) and [ADR-010](adr/ADR-010-programming-over-the-interface.md).

This is deliberately a source-evidence document, not a compliance claim. Issue #62 requires a complete inventory across transport, retry, breaker, resilient composition and bearer authentication before implementation changes. The inventory below records the public API families and export boundaries; the rows after it capture confirmed construction and encapsulation gaps.

## Phase and ownership distinctions applied

| Architecture rule | Egress interpretation | Evidence / enforcement to add |
|---|---|---|
| Configuration phase uses `with_<Trait>(value)` and caller-owned capabilities cross directly; it does not use request/response wrappers. | Builder/factory configuration values remain direct inputs. Do not wrap those capabilities in exposure DTOs. | Review each builder trait and factory signature; external-consumer compile tests. |
| Exposure operations use `get_*`/`list_*` with operation-specific requests and owned responses. | An operation returning policy or status must have its classified request/response pair. Direct identity/property accessors stay parameterless and use Rust accessor names. | Inventory every trait method and correlate each exposure operation with its DTO files. |
| VOs are immutable, have value semantics (`Clone`, `PartialEq`, `Eq`) and no mutation API. User-provided VOs have public construction; response-owned configuration VOs are constructed inside their response. The architecture scanner requires VO fields private. | Retry, breaker, resilience, channel and bearer configuration are caller-supplied inputs; callers need supported constructors/builders, while struct literals and unchecked deserialization must not create invalid completed values. | Compile-fail field/constructor tests; positive constructor tests; deserialization tests that assert invalid values fail. |
| Response-owned configuration VOs are created internally by their response constructor. | Do not apply this visibility rule to caller-supplied configuration inputs. Preserve the distinction between a caller's policy value and a configuration value created only as response data. | Classify each VO by ownership before setting constructor visibility. |
| Phase 2 requests use `new()` for zero or fewer than three parameters and a builder for three or more. They have private fields. Build requests are construction-phase parameter bundles with intentional public fields and are explicitly exempt. Responses have private fields. | Do not blanket-wrap identity accessors or rename build requests as exposure requests. | Request/response scanner and compile-fail constructor/field tests. |
| SAF modules are private; public factory types are canonically re-exported; implementation types stay opaque. | Consumers import root-level SAF factory exports and domain-owned traits/types. Contract types remain owned by `proto-pattern`; implementations do not duplicate them. | Compile-fail hidden-module tests and canonical-export scanner. |

### Export-boundary findings

All five domain crates expose their API through root-level re-exports and keep their internal `api` module private. The five implementation crates also declare `mod saf` privately and re-export their SAF factory types from the crate root, which matches the canonical factory path rule. `proto_pattern` is re-exported by transport, retry, and breaker as the contract namespace; resilient and bearer do not add that re-export.

`grpc-egress-transport-std` additionally root-re-exports `edge_security_runtime::SecurityContext` and SPI types `HealthCheck`, `HealthCheckRequest`, `HealthCheckResponse`, `HealthStatus`, `SecurityContextIdentity`, and `TokenCancellation`. These are public crate-root paths but are not SAF factories. They are an API-boundary exception requiring consumer/use-site evidence and explicit classification before removal or relocation; this audit alone does not treat them as violations. The other four implementation roots expose only SAF factories in their current `pub use` declarations.

Every domain crate currently declares `pub mod` submodules beneath its private `api` module, and root-re-exports selected types. Canonical consumer paths work through the root exports, but compile-fail doctests proving each hidden `api::...` path are not present in this inventory and the compile-time boundary still needs enforcement. Exposure DTO fields and constructors require the per-type visibility audit above; the inventory does not establish that every public type is canonical or that every operation DTO meets its exact constructor/field rules.

This table distinguishes caller-supplied inputs from values owned by another crate. The deployment architecture's public-constructor rule applies to caller-supplied values; its private-state/no-mutation/value-semantics requirements apply to VOs generally. The issue's acceptance criteria additionally require invalid policy values to be impossible to complete through literals or deserialization.

### Remaining VO-by-VO ownership and semantics inventory

| Public value | Ownership / role | Source shape | Remaining rule or evidence |
|---|---|---|---|
| `MtlsConfig` | Caller-supplied TLS identity configuration. | Three public string/optional-string fields; `Serialize`/`Deserialize`; no value semantics derives or validation constructor. | Private immutable state, public validated construction through the domain API, and deserialization validation; preserve path-based TLS behavior. |
| `KeepAliveConfig` | Caller-supplied channel policy with a valid default. | Three public fields (`Duration`, `Duration`, `bool`); `Default`, `Serialize`, `Deserialize`; no `PartialEq`/`Eq`. | Private immutable state, public construction preserving current defaults; establish and enforce valid duration bounds on every completion path. |
| `CompressionMode`, `BalancingStrategy`, `TraceContextSource` | Caller-selected enum options, not response-owned config VOs. | Public enums; `CompressionMode` and `BalancingStrategy` derive serialization; `TraceContextSource` currently derives `Clone` only. | Audit value semantics, public variant construction, and whether each enum is a VO or a capability/config option; no invalid struct-field bypass applies. |
| `BearerSecret` | Caller-provided signing credential. | Public enum variants expose key bytes; derives `Serialize`/`Deserialize` and `Clone`, but not `PartialEq`/`Eq`. | Preserve caller construction while hiding stored bytes behind validated constructors/accessors; classify whether serializing secret material is permitted and add compile-fail/serde/security tests. |
| `JwtClaims` | Upstream-owned security value, constructed through the local claims builder. | Re-exported from `swe_edge_security`; not locally declared. | Verify upstream ownership, field privacy, immutable value semantics, and ensure egress adds no duplicate type or alternate public path. |
| `BreakerState`, `Outcome` | Upstream-owned breaker policy values. | Re-exported from `edge_transport_breaker_policy`; not locally declared. | Verify canonical owner paths and visibility/value semantics; use the dependency API rather than introduce local copies. |
| `RetryDecision`, `ResourceExhaustedContext` | Local classification result values, not caller policy inputs. | Public fieldless enums deriving `Clone`, `Copy`, `PartialEq`, `Eq`. | No field-construction bypass; verify canonical root export and treat as results rather than validated configuration. |

The retry and resilience configs contain `f64` multipliers, so `Eq` cannot be derived with ordinary floating-point semantics. The issue must record the chosen value representation/semantic rule rather than claiming full architecture value semantics without resolving NaN and equality behavior.

These findings identify real construction bypasses; they do not prescribe request wrappers or redesign exposure APIs. Existing per-factory validation remains useful defense in depth, but it does not make an invalid public VO impossible to construct.

## Remaining evidence required before implementation selection

- Complete the ownership and invariants matrix for each individual VO, including `MtlsConfig`, `KeepAliveConfig`, `BackendTarget`, `LoadbalancerSettings`, bearer configuration and externally owned `JwtClaims`; distinguish simple enums and identity/property values from validated configuration.
- Map every operational trait method to a Phase 2 operation, a Phase 1 construction/configuration method, or a direct accessor. Resolve `TlsSettingsResolver::resolve`, config-provider parsing/validation/conversion methods, and interceptor callback context against the exact pinned rules.
- Check all re-exported health/SPI types against external use sites and prove canonical paths/private implementation boundaries with compile-fail tests.
- Resolve whether the extra transport-std root exports are intentional public API, then add a canonical-export/hidden-module enforcement check.
- Recheck source paths and line-level evidence at the implementation commit, and record the required scanner or test for every row.
- Separate egress-local changes from changes that need released `proto-pattern`/`proto-svc` APIs. Keep #61's unaccepted cross-cutting migration outside this issue.
